# Val-valued global maps that are deliberately NOT GC roots. One per line:
#   <map name>  <why its values never need marking>
# tools/gc_roots_check.sh fails on any Val-valued map that is neither a root
# nor listed here, and on a listed map that has since become a root.
arr_store     the collected array store itself: reachable arrays are marked through VArr, the rest is what gets dropped
fb_env_at     the env of the frame at each call depth, read only by the fiber reclaim pass for the depths each stack has live; an ordinary collection runs where no frame is live, and every depth above a stack's current one is stale
ivars_g       the world's instance-variable table itself (it was a local of run_src until a Fiber's thread needed to find it): gc_collect keeps the entries of marked owners and drops the rest, so it is the collector's subject, not a root
curry_arity   VInt only (the arity a curried proc waits for)
curry_target  VInt only (the id of the proc a curried one calls; gc_mark_val marks it when it marks the curried proc)
proc_origin   VInt only (the id of the proc a copy came from; only compared and used as a key, never looked up in proc_store)
r2k_marks     VNil only (a set of hash ids marked ruby2_keywords)
r2k_procs     VNil only (a set of proc ids flagged ruby2_keywords)
vis_marks     VNil only (a set of "cls#name" where a visibility statement named a method)
tl_vis   VBool only (the default visibility for top-level defs: true = public)
num_names_memo  the inner maps hold VNil only (one name-set per numeric kind); the only writer is `map_set m9 h9 VNil` and the only reader is `num_has`
arr_pending	appends queued for an array (and the whole array in its Vec form, note 278) not yet folded into it: the collector reaches them through VArr like the array's own elements (arr_each_val reads the queue where it is), and its sweep drops the queue of a dead array beside the array
arr_vc	the Vec a fold turned back into an array's list, kept for the next write while the array's version is unchanged: the same values the list holds, so nothing here needs marking of its own; a stale one is never read, and the sweep drops a dead array's
hash_pending	pairs queued for a hash but not yet folded into it: the collector reaches them through VHsh like the hash's own pairs (hderef folds them in before gc_mark_vals sees the list), and its sweep drops the queue of a dead hash beside the hash
hash_index	the digest index beside a hash: its values ARE the hash's own values (hpush_new writes both), so it holds nothing the hash does not, and its sweep drops the index of a dead hash beside the hash
eq_seen	VInt only (pairs of container handles currently being compared by ==; the marker is 1, never a value, and it is deleted as the comparison unwinds)
frz_busy	VNil only (a re-entry flag for the inspect inside a FrozenError message; the map holds one key and its presence is the whole value)
closed_ok	VNil only (the eight method names a CLOSED File still answers; the map is a SET -- membership is the whole value and nothing reachable is stored in it)
io_reads	VNil only (the method names that MOVE BYTES OUT of a stream, so a handle not opened for reading can refuse them; the map is a SET -- membership is the whole value and nothing reachable is stored in it)
io_writes	VNil only (the method names that MOVE BYTES IN to a stream, the write-direction half of io_reads; the map is a SET -- membership is the whole value and nothing reachable is stored in it)
stdlib_ran	VNil only (the shipped library bodies that have already run; the map is a SET keyed by the source text -- membership is the whole value and nothing reachable is stored in it)
bm_bypass     VNil only (a flag: set while a Kernel method bound to an object runs on it)
proc_store    the procs themselves: a proc is marked through VProc (gc_mark_val marks its env, its yield block and a curried target), and gc_collect sweeps the ones nothing reached (note 270)
gc_off_env    the env a collection run off the stack is handed (gc_collect_any): set just before the switch, passed to gc_collect as its env -- rooted there -- and deleted after
proc_yblk     the block each proc yields to, beside it by id: marked with its proc (gc_mark_val), and named by the yield-block markers read from live procs, the method table and yblk_pin; swept with its proc (note 270)
lv_cap        the captured frames that have left the stack, by frame id: NOT a root on purpose -- each is reached through what holds it (a live proc, a binding, a stack frame, a child scope; gc_mark_env), and gc_sweep_captured gives back the ones nothing reached (note 272)
lv_capx       the scope envs lv_child made (eval, instance_exec, class_exec) whose run is over and that a proc captured, by frame id: NOT a root on purpose, as lv_cap -- reached through what holds them (gc_mark_env); gc_sweep_captured drops the links of the ones nothing reached (note 272)
