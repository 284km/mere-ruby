# The last file the native compiler declined: a hash pattern's key

After round 63 no corpus program falls back to the evaluator under MERE_RUBY_VM. One was still declined by the native compiler and compiled by the Ruby one, which runs on mere-ruby itself and takes many times as long: corpus 377, for `in {"a-b": 1}`.

## The key in the error

A hash pattern that fails by a missing key raises NoMatchingPatternKeyError, "{}: key not found: :\"a-b\"". The message is made when the pattern is compiled, of the key's `Symbol#inspect`. The native compiler made it only for a plain identifier, and declined the file for any other key.

It now writes `Symbol#inspect` (`ic_sym_inspect`):
- `:name` for a name ruby writes bare: an identifier, with `?`, `!` or `=` after it; a constant's; an instance, a class or a global variable's; an operator a method can be named;
- `:"..."` for any other, escaped as a String's inspect escapes: `"`, `\`, `#` before `{`, `$` and `@`, the named control characters, and `\xNN`.

A quoted name with a character past ASCII in it is still declined: how that is written depends on the character.

Checked by the chain: for a file with 41 keys of every kind in one `case`, ruby's own sequence is the Ruby compiler's, and the Ruby compiler's is the native one's.

## A Hash as raise's message

Corpus 821, written for the keys, ended with a `case / in` no branch of which matches. On the VM its message was wrong:

```ruby
case {a: "s"}
in {a: Integer} then 1
in {b: _} then 2
end
# NoMatchingPatternError: {a: "s"}        -- ruby, and the evaluator
# NoMatchingPatternError: NoMatchingPatternError   -- the VM, on main too
```

ruby's instructions for it are `raise NoMatchingPatternError, value`, and the VM runs them as that. The defect is `raise`'s, on **both** executions:

```ruby
raise ArgumentError, {a: 1}    # message: "{a: 1}"; here "ArgumentError"
raise ArgumentError, h         # the same
raise ArgumentError, foo: 1    # "{foo: 1}": keywords that are not cause: are the message
```

A Hash in the message's place was "left to the keywords it may be", and then nothing read it. It is the message now, as any object is; only keywords that are none (`**{}`) are no message.

**And the evaluator's own no-match error** was the value's inspect, where ruby's is what `raise` makes of the value, its `#to_s`:

| the value | ruby, and the VM | the evaluator |
|---|---|---|
| `nil` | "NoMatchingPatternError" | "nil" |
| `"a string"` | "a string" | "\"a string\"" |
| `:sym` | "sym" | ":sym" |
| an object | its `#to_s` | its `#inspect` |

It is the `#to_s` now.

Corpus 822 has the raise forms (a Hash literal, a variable, keywords, `cause:` with them, a class with its own `#initialize`) and a `case / in` over each kind of value.

## Recorded, as on main, on both executions

- A rightward pattern match as a statement inside parentheses is a SyntaxError: `x = (h => {a:}; a)`, `def k(h) = (h => {a: 1}; :ok)`. ruby reads it. (`(h in {a: 1})` is read.)
- An exception keeps its message as a String made at the raise. A Hash given as the message whose `#to_s` is defined on that one Hash (`def h.to_s`) says its inspect; ruby asks the Hash.

## What the native compiler still declines

Of the corpus's 876 main scripts, none. Among the files those programs require or run (`MERE_RUBY_VM=report` names each), five, for two reasons:
- a BEGIN block (three): the evaluator's by design, since it keeps the order a BEGIN runs in;
- a top-level `return` with a value (two), which the Ruby compiler takes.
