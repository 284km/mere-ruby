# The native compiler's sequences are loaded with no Array or Hash made of them

Round 60 left the VM's Rails boot at 1.03 times the evaluator's instructions, and named what was on top: the native compiler's sequences made into the Arrays `RubyVM::InstructionSequence#to_a` has, and the loader reading them back. This round removes the Arrays.

## What a compile made

For a file the VM runs, the native compiler (`ic/`) answered what the Ruby compiler answers: the tree `#to_a` shows. `ic_to_val` made it of Ruby objects:
- an Array for each sequence, for its body, and for **each instruction**;
- a Hash, frozen, for each calldata, for the parameters and for `misc`;
- an Array for the local table, the catch table and each entry of it, each constant path.

The loader (`vm_load`) read them once and dropped them. A sample of the Rails boot had 407 of 7,246 samples in `ic_to_val`, more than half of them the object table's insertions, its copies and their allocation, and 211 in the loader, a fifth of that reading the Arrays back. A later collection then swept every one of them.

## The change

The compiler's value type has two new forms for a sequence's **structure**: `IvLst`, a list, and `IvRec`, a record. `ic_to_a` uses them for everything in the list above. A literal an instruction carries (a `duparray`'s Array, a `duphash`'s Hash, a calldata's `kw_arg`, a case dispatch's table) is still `IvArr` or `IvHsh`, and still becomes the Ruby object the VM keeps as the operand.

`ic_to_val` makes of the two a `VIcl`: a list of values, held in the compile's region. It is a new constructor of `Val`, and it is **not a Ruby value**. It lives from `ic_to_val` to `vm_load`, and no instruction's operand is ever one.

The loader reads a structure through three functions, `vm_lst`, `vm_is_lst` and `vm_rec`, which take the Ruby compiler's Array or Hash and the native compiler's list alike. So there is still one loader and one decoder for both compilers.

`ic_vm_native` now compiles **and loads** inside its region, so the list never leaves it. It answers what happened and not a value:

| | |
|---|---|
| 2 | the program is loaded, and its id |
| 3 | the loader refused what was compiled, and why |
| 1 | the compiler declined, and why |
| 0 | nothing (a syntax error; or, asked before the parser, a source Prism has a warning of) |

`tools/iseq/native/check.sh` compares the text of the two compilers' trees. The text writes `IvLst` and `IvRec` as the Array and the Hash they stand for, so it is unchanged.

**Where a `VIcl` would be a defect.** Four functions match every constructor of `Val` with no default: `class_name`, `to_s`, `rb_eq_go` and `bi_reg_set`. Each has an arm for it that fails with "a compiler's list where a value is read". If one ever reached a Ruby program, the program would stop there and not go on with a value of no class.

**What is left of the compile.** A sample of this boot has the native compiler and the loader at 14% of it (806 of 5,685 samples): the compile itself 239, Prism's parse and serialization 148, the loader 134, `ic_to_val` 115, `ic_to_a` 94. The last two could be one pass. Past that, a file's compile is what it costs to compile it, and not paying it twice is a cache of compiled sequences on disk, which is another piece of work.
