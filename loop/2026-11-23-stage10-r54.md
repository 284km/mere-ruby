# `!` on the VM without a scope, and an Array's or Hash's element asked by its own singleton #==

## `!x` (`not x`)

so_lists's loops are `while (not li2.empty?)`. On the VM, `!` is a send. vm_call_in made EUn of it in a scope (vm_scoped), the way it makes an operator's EBin. That cost 5.6k instructions a call, where the evaluator's EUn costs 1.7k.

EUn's arm for `!` is short. If the receiver's class has a #!, it calls it: an object's class, or dispatch_cls_of for a builtin value, which counts a #! defined on NilClass or on Object too. Otherwise it answers the truth turned over. vm_call now does the same when no TracePoint is on, with no scope.

- `not a.empty?` (300k): evaluator 3.78 G, VM 4.34 G → 3.11 G.
- so_lists: 1.14x → **1.04x** the evaluator's instructions.

**Left, as on main (both executions):** a singleton `!` on a builtin value is not found. With `def s.! = :x` on a String, `!s` and even `s.!` answer false. The method dispatch does not look in a builtin value's singleton class for `!`. That is beyond this path, which only does what EUn does.

## Elements whose own #== is a singleton's (from the review of #184)

With `x = +"k"; def x.==(o) = true`, ruby gives true for `[x] == ["zzz"]` and `{a: x} == {a: "zzz"}`. Here they gave false, on both executions and on main. There were two reasons.

- arr_has_obj (and so hash_has_obj), which decides whether two containers are compared by their elements' #==, counted an object and an exception. It did not count a builtin value whose singleton class or subclass has #==. prim_eq_override now counts it.
- cmp_member_w, which compares two elements, asked only an object's #==. If the left element is such a value, it now calls its #==. Two identical elements are equal without a call, as rb_equal has it.

There was also a shortcut. EBin's arm and vm_bin_eq_ok called two structurally equal containers equal before asking whether they held such an element. With `def y.==(o) = false`, `[y] == ["k"]` is false in ruby, and it was true here. The question is now asked first. That costs one walk of the elements also when the two are equal, which the arm already paid when they were not.

Corpus 811 has both changes. It differs on main's build on both executions.
