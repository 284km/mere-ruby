# Rails-2: super from a hook prepended to Module reaches Module on an object's singleton class

**Why.** In round 2 of activerecord (main 8c39dd51), inheritance_test stopped at load on the mere-ruby side, with all 74 of the reference's cases never reached:

```
zeitwerk/core_ext/module.rb:16:in 'Zeitwerk::ConstAdded#const_added': super: no superclass method 'const_added' for class (sng:281474976714659) (NoMethodError)
	from tmpdir.rb:157:in 'singleton class'
```

Zeitwerk prepends a `const_added` to `Module` and ends it with `super`. tmpdir.rb defines a constant inside `class << obj`. The receiver of the hook is then the singleton class of an object.

**The cause.** `super_base` names the class whose chain a `super` walks. For a class receiver that is its singleton, and the singleton of a class was passed through as written, because its chain already ends in Class and Module. The singleton class of an OBJECT went the same way, but its chain as written is the object's: its class, Object, Kernel. No Module is in it, so the super from the prepended method had nowhere to go.

**The change.**

- **`super_base`** answers the metaclass for the singleton class of an object or a value (`sng_of_value`: "(sng:<id>)", "(sng:str:12)"). That chain reaches Class and Module.
- **`const_added_hook`** names the owner through `const_owner_scope`. A class written in `class << self` is keyed by its cref, "K::(sng:K)::In", and the hook was called on a class of the name "K::(sng:K)". ruby calls it on the singleton class.

**Corpus 969** has a hook prepended to Module that records its receiver and calls super, over: a module, a `class << self` constant, an object's singleton class, a class and a module written in `class << self`, `const_set` on an anonymous class and on its singleton class, and a String's singleton class. It also calls `const_added`, `method_added` and `included` by name on an object's singleton class. It matches ruby 4.0.9 with and without `MERE_RUBY_VM=1`.

**On a build of main 17a5db5f and this:** inheritance_test runs to the end, 74 cases, MATCH 0 → 73, RED 1 ("ActiveRecord::SubclassNotFound expected but nothing was raised", for a later round).

**Checked.** On main 507d44c3 and this: `run_corpus.sh --both` 857/857, `MERE_RUBY_VM=1 run_corpus.sh --both` 857/857, and the source gates (dead_defs, dup_defs, gc_roots, meth_writes, name_len, ns_names, bracket_depth). No other corpus run was going, and the worktree was not touched from the build to the end of both passes.
