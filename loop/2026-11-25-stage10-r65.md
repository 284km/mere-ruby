# A top-level return with a value, and ruby's warning of it

After round 64 the native compiler declined nothing in the corpus's main scripts. Among the files those programs require, it declined two reasons: a BEGIN block, the evaluator's by design, and a top-level `return` with a value. This round compiles the second.

## What ruby does

A file's own `return` ends the file, and a value given to it goes nowhere. ruby says so as it compiles the file, before any of it runs:

```
D/lib.rb: warning: argument of top-level return is ignored
```

- once for each such `return` of the top level, a rescue or an ensure clause's included (one in a method or a block is another scope);
- with the file and no line;
- for the main script, a required file and a loaded one alike;
- not under `-W0`.

The compiled sequence is the plain return's: the value is pushed and the frame left.

## What it was here

| | ruby | the evaluator | the VM |
|---|---|---|---|
| when | at the compile, before the file runs | after the main script had run, the last thing printed | at the compile |
| how often | once a return | once, for the main script's one that ran | once a return |
| where | the file | the file | the file and the line |
| a required file's | said | not said | said |
| a loaded file's | said | not said | not said (it runs on the evaluator) |

## The change

- **The native compiler** compiles the return and counts it (meta 11). `ic_vm_native` says the warning that many times once the file is loaded.
- **The Ruby compiler** says it with the file and no line, and of a rescue or an ensure clause's return too.
- **The evaluator** counts a file's top-level returns of its statements (`top_ret_args`, which now looks through a rescue clause, `and` / `or` and a statement's wrapping) and says the warning before the file runs: the main script, a required file the VM does not take, and a loaded file. A file the VM takes is told of by its compiler.
- The parse's own warnings are said before the compile's, as ruby's are: "statement not reached" comes first.

## Found on the way: a magic comment that was only a mention

With the Ruby compiler in use (`MERE_RUBY_IC=ruby`), every run said

```
.../__iseq_compiler.rb:3747: warning: invalid value for shareable_constant_value: a
```

That line is a comment of round 63's: `# pm_compile_shareable_constant_value: a literal is pushed...`. The evaluator's lexer took the name anywhere in a comment for the magic comment. ruby takes it only as the comment's key: right after the `#`, or after a `;` or the `-*-` of the emacs form. So `# a-shareable_constant_value: literal` and `# foo shareable_constant_value: literal` are no magic comment, and here they were. The lexer reads the key's place now.

**And the embedded copy was stale.** mere-ruby carries the Ruby compiler as a string, generated from `lib/iseq_compiler_ext.rb` into `m_pathname_lib.mere` by `tools/gen_pathname_lib.rb`. Round 63 (#233) changed the lib and did not regenerate the copy. So on main the Ruby compiler that mere-ruby runs still declined the shareable constant writes that round 63 taught it, and `compare_files.rb`, which runs the lib under ruby, could not see it. The copy is regenerated here, and the CI checks #232 proposed, in a PR that follows this one, check that it is current.

## Numbers

The native compiler now declines, among every file the corpus's programs require or load, only the BEGIN blocks: three files.

Corpus 823 runs children and reads their two streams as one: a main script, two required files with returns in an `if`, a `begin` with `rescue`, `else` and `ensure`, a block, a method and an `and`, a loaded file, a bare return; under no flag, `-W0` and `-w`. And the magic comment's forms. It matches ruby on both executions, and on the VM through the Ruby compiler too; on main's build it differs on both.

## Recorded, as on main: the VM through the Ruby compiler

The Ruby compiler is the VM's when the native one declines a file, which in the corpus is nowhere now, and under Coverage's branch mode, where it is the one that compiles the branches in. With it forced for every file (`MERE_RUBY_IC=ruby`), three corpus programs differ from ruby: 675, 725 and 819. They differ the same way on main's build. 819 is round 62's literal Hash key, which the native compiler's values intern and the Ruby compiler's do not. Four more fall back there, the sources in other encodings, which the Ruby compiler does not take.
