# RubyVM::AbstractSyntaxTree::Node keeps its values in two native tables, not in instance variables

The frame rework's test_ast item, option (B) of note 552 §17.8: test_ast's tree objects held most of the program's instance variables.

**Before.** ast_obj_build gave each Node seven instance variables, and `@__xl` on a node with more locations:
- `@type`, `@children`, the four positions and `@node_id`;
- `@__ast`, the tree's [script lines, tokens], on every node.

A tree of a ruby test file is about a million nodes, and test_ast builds three trees of each of its files. Each instance variable is a string-keyed entry in the one ivars map ("<id>@type"). That map was the largest thing the collector walked and swept in test_ast. ruby's Node is a C object with no instance variables, so `instance_variables` answered seven names where ruby answers `[]`.

**Now.**
- `ast_node_pos` maps the object id to (type number, first_lineno, first_column, last_lineno, last_column, node_id), all ints.
- `ast_node_vals` maps the object id to (children Array, the other locations or nil, the tree's shared [script lines, tokens]).
- Both tables are int-keyed and live in m_state.mere, and `gc_churn_bytes` counts them.
- The collector:
  - marks a Node's three values through gc_mark_val's VObj arm, where it marks `method_cores`;
  - drops both tables' rows by the dead object ids (`gc_drop_i … dOC`), as it does for `method_cores`;
  - compacts the tables.
- `tools/gc_roots_allow.txt` says why `ast_node_vals` is not a root.
- Object ids only grow (`alloc_oid`), so a row can never be read by a later object with the same id.

**The readers.** type, children, the four positions, node_id, script_lines and all_tokens are methods of Node in the prelude, `def type = self.__nd_type` and so on. They are rows of the method table, as ruby's are. The table answers `__nd_*` (`ast_node_get`) in invoke_val_c0's VObj dispatch, and only when self is that Node.

**The fast path.** A Ruby method per read cost a frame. test_ranges (part 3) went from 828 G to 1,141 G, and part 4 from 411 G to 583 G. So a reader is answered from the table with no frame (`ast_reader_fast`) when all of these hold:
- the method is still the prelude's own: `set_meth` notes that its body is `self.__nd_<name>` (`ast_reader_ok`), and a def over it, an alias onto it or a removal takes it out;
- the receiver is a plain Node, with no singleton class;
- nothing is prepended to Node, and no refinement exists;
- the reader is neither private nor protected;
- no TracePoint is on;
- the call has no arguments.

Otherwise the call goes the way of any method. The path is in invoke_val_c0's VObj dispatch and in the two bare-call paths (try_self_call_x and try_self_call1). test_ast's Helper and pp call the readers bare.

Ruby's own methods follow ruby's ast.rb:
- `#source` and `#tokens` call the readers by name.
- `#inspect` and `#locations` read `__nd_*` (and `__locations`) directly. Ruby's are Primitives, which a program's own `def type` does not change.

**Like ruby's C object** (corpus 812):
- `instance_variables` is `[]`, and `instance_variable_get(:@type)` is nil.
- `dup` and `clone` raise TypeError "allocator undefined for RubyVM::AbstractSyntaxTree::Node", and `Marshal.dump` raises "no _dump_data is defined for class RubyVM::AbstractSyntaxTree::Node" (Node is in Marshal's UNDUMPABLE).
- The readers are Node's own methods: `instance_method`, `method_defined?`, `public_methods(false)`, arity 0, `alias_method`, `private`, `super` from a prepended module, `remove_method`, and a program's own `def`. They come before what Object and Kernel define.
- `n.__nd_type` from outside is a NoMethodError, as is a bare `__locations` in a program's method.

On main these differed: seven instance variables, a copy, and a dump.

**Left, as on main:**
- `node_id` counts from 0, parents first; ruby numbers nodes in the order its parser made them. Nothing looks a node up by it here (`of` raises).
- An error_tolerant tree's last column (`def f(\n` ends at 1:6, ruby 1:7).
- An empty file's tree from `parse_file`: ruby's `source` raises there.

## Review of #199

**[Major] The readers lost to Object and Kernel, and [Major] reflection went back.** As first written, the readers had no row in the method table. They were builtins answered after every method lookup missed:
- `has_meth` searches the ancestors, so `class Object; def type = :x; end` made `n.type` `:x`, and `module Kernel; def children` broke `pp` of a Node.
- `Node.instance_method(:type)`, `alias_method`, `private :children` were NameErrors.
- `method_defined?(:children)` was false, `public_methods(false)` was `[]`, and `super` from a prepended module was a NoMethodError.
- `method(:type).arity` was −1, where ruby has 0.

Main passed all of these with attr_reader rows.

The fix is the review's suggestion: each reader is a row of Node's method table, `def type = self.__nd_type`. With that, several things the first version needed are gone:
- the bare-call arms in try_self_call_x and try_self_call1;
- Node's entry in the reflection lists;
- remove_method's special case.

Remove, undef, alias, private and super work as for any method.

**[Minor] `__nd_*` and `__locations` answered from outside.** The AST stream found this too. They now answer only when self is that Node, which means its own readers, `#inspect` and `#locations`. `n.__nd_type` is a NoMethodError, and a bare `__locations` in a program's method is a NameError.

Corpus 812 has every case, matching ruby on both executions.

**[P2, the automatic review] dup / clone refused a program's own.** The TypeError arm came before the method lookup, so `class Node; def dup = :custom_dup; end` raised. It now refuses only when nothing in the Node's dispatch class or its ancestors defines the name: Node, a prepended module, the singleton class or Object. Probed on both executions, directly, through send and through public_send.

**Recorded, as on main:** under a TracePoint, a reader is a `:c_call` / `:c_return` (the prelude's methods are reported that way), where ruby fires `:call` / `:return`, as its ast.rb methods are Ruby.

**Recorded, as on main:** `B = A; class B; def zz = 1; end` does not reopen A, so `A.new.zz` is a NoMethodError. Ruby reopens A.

## Second review of #199

**[Minor] `__nd_*` answered whenever self was the Node.** A method a program adds to Node (`def mine = self.__nd_type`), `n.instance_exec { self.__nd_type }` and `n.instance_eval { __nd_type }` got `:SCOPE`. Ruby and main raise NoMethodError (NameError for the bare form).

The table now answers `__nd_*` only when the calling frame is a method of Node that the prelude wrote (`ast_nd_caller`):
- the frame's defining class is Node;
- its method is marked `meth_cfn`, the mark the prelude's methods get;
- the method is asked by the name it was called by, so an alias of a prelude reader stays one even after the program writes its own method under the old name.

The fast path asks for the same mark. Before, a program's own `def type = self.__nd_type` had the prelude's shape, and the evaluator answered it from the table.

**[Minor] `Kernel.instance_method(:dup).bind_call(n)` made a Node with no rows.** Its readers then failed with "undefined method '__nd_type'". The refusal was an arm before the method lookup, and a bound Kernel#dup did not pass it.

The refusal is now at the copy itself, the VObj dup / clone primitive. A program's own dup or clone is found before that arm as any method is. A bind_call of Kernel's, or a `super` into it, arrives there and is a TypeError.

**Recorded, as on main:** `def dup = super` answers self, in any class. Ruby's copies.

**MERE_RUBY_VM=0** turned the VM on. It is the evaluator since #200. The measurements here set the variable only for the VM and unset it otherwise.
