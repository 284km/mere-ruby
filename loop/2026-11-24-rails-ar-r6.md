# Rails-2: a yield in a define_method body is the enclosing method's block

One more cause from round 2 of activerecord (main 8c39dd51). Of the 22 RED around migrations, 19 are "An error has occurred, this and all later migrations canceled: no block given (yield)", and this is their cause. The other 3 are #197's (below).

**The shape.** migrator_test wraps a migration to watch it run:

```ruby
def m(name, version)
  x = Sensor.new name, version
  x.extend(Module.new {
    define_method(:up) { yield(:up, x); super() }
    define_method(:down) { yield(:down, x); super() }
  }) if block_given?
end
```

A `yield` in a define_method body is the block of the method the body was written in. It is called whenever the defined method runs, also after that method has returned.

**What worked and what did not.** The body's frame is a child of the env its block was written in. The bare `define_method` in a method keeps the block in force (`dm_captured`). A `class_eval { }` block carries its method's block in its env (`yblk_env`), where the yield finds it. Three forms had neither:

- a `Module.new { }`, `Class.new { }` or `Struct.new(...) { }` block;
- `define_method` with a receiver (`k.define_method(:go) { yield }`);
- `define_singleton_method`.

**The change.**

- **`yblk_blk`** gives the block of `Class.new`, `Module.new` and `Struct.new` an env that carries the enclosing method's block, as `class_eval`'s does. Without a block in force the env is the block's own, unchanged.
- **`dm_capture_blk`** keeps the block in force for the two receiver forms, as the bare form keeps it.

**Corpus 967** has the migrator's shape (with `super()` after the yield, called three times), the three block forms and a nested one, the two receiver forms, `class_eval`, a method called without a block (LocalJumpError), `block_given?` in the body, and a proc. It matches ruby 4.0.9 with and without `MERE_RUBY_VM=1`.
