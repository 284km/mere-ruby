# Reference Ruby 4.0.10

The active reference is Ruby 4.0.10, tag `v4.0.10`, source
`a704b7cd95a42cc0cf5f307137bf3aac0285b915`. Ruby reports its release date as
`2026-11-19`; the public release announcement was posted on November 18.
The ordinary CI, current gem/Rails locks, runtime identity, RbConfig and the
C API `ruby_version` constant use that release together.

The source inventory remains 758 `test/` files (761 execution units after
splitting `test_ast.rb`), 34 bootstrap files, one basic body, 12 tool/test
bodies and 3,783 ruby/spec candidates. An unchanged file count does not mean
unchanged cases: the source update includes new regression cases and ten
additional C API Proc examples.

Compatibility adjustments include JSON 2.18.3's Ruby sources and malformed
control-byte escape rejection with unchanged default diagnostics; explicit single-byte Integer#chr errors;
character formatting errors; the upstream Socket changes; the ISeq
IGNORE_REFINEMENTS flag and refreshed builtin disassembly; and the changed
upstream C API headers and vendored C sources.

The package snapshot keeps its original source/package digests. Gem suite
locks change only their Ruby version and source revision. Comparing with a
4.0.9 baseline reconstructs its old lock and verifies its exact digest;
source, package, command and test inventory changes are still rejected, as
are missing results, regressions and changed reference coverage. Historical
results keep their original version. Fixed-source resource experiments
continue to replay their original 4.0.9 conditions rather than relabeling
captured evidence.

The reference-version, JSON diagnostic and formatting witnesses are
`corpus/980_reference_ruby_release.rb`,
`corpus/981_json_control_character_escapes.rb` and
`corpus/982_format_character_encoding_errors.rb`. They use the process/CI
range and leave 960–979 to the Rails activerecord stream.

## Follow-up review corrections

The native ISeq compiler now gives the initialize call after opt_new the same
FCALL and IGNORE_REFINEMENTS flags as the Ruby compiler. The native compiler
comparison over all 857 corpus files reports 855 identical, one refused,
zero different and zero failed; one file is not compiled by the Ruby compiler
either. The existing refusal is preserved.

Integer#chr applies the Ruby 4.0.10 generic single-byte rule to dummy
encodings too, using the existing enc_is_dummy classification after canonical
name resolution. Corpus 982 adds ten boundary values for nine dummy encodings
and two aliases, and compares successful bytes/encoding names or the error
class and full message. Character formatting keeps its separate encoding
classification.

ONBOARDING and the current Rails application/framework usage instructions
now name Ruby 4.0.10. Historical Rails measurements keep their original
reference versions. The JSON generator header names its actual 2.18.3 input.
Final-head corpus, VM, source-gate, upstream-file and C API replay results are
reported in PR #208; the runtime is rebuilt at ordinary O2 after these fixes.
