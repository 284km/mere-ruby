# Rails-2: Array#delete answers the element it deleted; a superclass written `::Name` is the top-level one

Two small causes, found on the files that ran to the end after #211 and #213.

## Array#delete answers the element it deleted (nested_attributes_test, 6 RED)

`Array#delete(obj)` answers the last ELEMENT it deleted: `rb_ary_delete` keeps the element each `e == item` matched. It answered its argument. The two are different objects whenever `==` is not identity.

`ActiveRecord::Associations::CollectionAssociation#merge_target_lists` does `mem_record = memory.delete(record)` to find the in-memory record that a freshly loaded one stands for. The in-memory one has the unsaved changes and the marks for destruction. It got the loaded one back, so `pirate.birds_attributes = [{ id: 1, name: "Grace OMalley" }]` followed by a load read "Posideons Killer".

- **`val_delete_w`** makes one pass and answers the elements that stay, whether any went, and the last one that did. Both forms of `delete` use it: with an argument, and with a block for "not found".
- Each element's `==` now runs once, as in ruby. It ran twice (a membership pass, then a removal pass).

Corpus 971: what is returned for equal objects, the block form, the calls `==` receives and their order, plain values (`[1.0, 1].delete(1.0)` is the Integer), and a frozen array.

## A superclass written `::Name` is the top-level one (inheritance_test, 1 RED)

The parser dropped the leading `::` of a superclass, and the name was then looked up from the scope. In activerecord's test models:

```ruby
module Namespaced
  class Company < ::Company; end
  class Firm < ::Company; end
end
```

`Firm` became a subclass of `Namespaced::Company`, so `Namespaced::Company.new(type: "Firm")` raised no SubclassNotFound.

- **The parser** keeps the `::` in the superclass's name.
- **`named_class_of_al`** resolves a name that begins with `::` from the top.
- **`class K < expr`** passes the class its expression answered by its name from the top. It was passed as a bare name and looked up again from the scope. The VM hands every superclass over this way, so under `MERE_RUBY_VM=1` the plain `class Firm < ::Company` went wrong there too.

Corpus 972: the models' shape, a plain name beside it, an expression, an anonymous class, a `::A::B` path, a reopen with another superclass (TypeError), a `::` name that does not exist (NameError), and a module nested in a module.
