# Rails-2: named captures beside plain groups bind the right locals (the sqlite3 adapter's index SQL)

**Why.** In round 2 of activerecord, 92 RED came from the sqlite3 adapter reading an index's SQL: `undefined method 'size' for nil` in `IndexDefinition#concise_options`, `'strip' for nil` in the schema dumper, and index tests reading a wrong expression. The adapter's `indexes` does this:

```ruby
/\bON\b\s*"?(\w+?)"?\s*\((?<expressions>.+?)\)(?:\s*WHERE\b\s*(?<where>.+?))?(?:\s*\/\*.*\*\/)?\s*\z/im =~ index_sql
```

and then uses the locals `expressions` and `where`.

**The cause.** `/literal/ =~ str` binds a local for each named group. Beside a named group a plain paren does not capture, so it has no number. `set_named_caps` counted it anyway when it bound the locals. Each local then got the capture of the group after it: `expressions` was the WHERE clause, or nil, and `where` was nil. Every table with an expression index or a partial index failed to load its indexes.

**The change.**

- **`set_named_caps`** does not number a plain paren. Only a pattern with a named group binds anything, and there a plain paren has no number.
- **`rx_ref_names`**, which turns `\k<name>` in a replacement into a number, had the same count and has the same change.
- **nil on the right.** `/(?<a>x)/ =~ nil` is a match that failed: the locals are nil and `$~` is nil. The evaluator left the locals unbound ("undefined local variable"). An index with no SQL of its own (a primary key's) takes this path.
- **`$~` after nil.** `re =~ nil`, `re === nil` and `re === 5` now leave `$~` nil, as `re.match(nil)` did and as `rb_reg_eqq` does. They left the last match standing. The VM reads the named locals from `$~` after the call, so there the local got a group of the previous match, or an IndexError.

**Corpus 964** has the adapter's pattern over seven index definitions and nil; plain groups before, between and after named ones; a nested one; a failed match; a Symbol on the right; `\k<name>` in `sub` and `gsub`; and `$~` after each way of matching nil. It matches ruby 4.0.9 with and without `MERE_RUBY_VM=1`.

**On this build**, RED before → after, with no MATCH lost:

| file | RED |
|---|---|
| adapters/sqlite3/sqlite3_adapter_test | 11 → 0 |
| schema_dumper_test | 7 → 0 |
| migration/index_test | 1 → 0 |

The other RED of this group are in files whose schema has such an index; the next full round counts them.
