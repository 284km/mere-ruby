# Rails-2: a double splat starts the keyword hash of a command call

**Why.** In round 2 of activerecord (main 8c39dd51), two files stopped at load on the mere-ruby side with 182 of the reference's cases never reached: delegated_type_test and nested_attributes_test.

```
associations.rb:1824:in 'ActiveRecord::Associations::ClassMethods#belongs_to': wrong number of arguments (given 3, expected 1..2) (ArgumentError)
	from delegated_type.rb:232:in 'ActiveRecord::DelegatedType#delegated_type'
```

Line 232 is a call without parentheses:

```ruby
belongs_to role, options.delete(:scope), **options, polymorphic: true
```

**The cause.** In a call without parentheses, `**options` went on the positional list. The pairs after it then made a second hash, so the callee got two. With parentheses the call was right: there a `**` goes on the keyword list beside the pairs. An empty `**options` hid it, because an empty splat adds nothing; `delegated_type` with any other option showed it.

**The change.** `parse_puts_args_go`: a `**` followed by a comma starts the call's keyword hash. What follows it (more pairs, another `**`, a `"str" => v` pair) is parsed into the same hash, in source order, and a block-pass may end it, as after a bare hash that starts with a pair. A `**` with nothing after it stays the one splat argument it was.

**Corpus 968** has the shape; a splat before, between and after pairs; two splats; an empty one; a string key; a block-pass and a block after it; a receiver; a method's last statement; a callee that takes no keywords; and `p` with a splatted hash. It matches ruby 4.0.9 with and without `MERE_RUBY_VM=1`.

**On this build**, both files run to the end:

| file | cases | MATCH | RED |
|---|---|---|---|
| delegated_type_test | 0 → 13 | 0 → 12 | 0 |
| nested_attributes_test | 0 → 170 | 0 → 164 | 6 |

The 6 RED are separate (a record's attribute read back as another value, `marked_for_destruction?`) and are for a later round.

**Checked.** On main 17a5db5f (with #197) and this: `run_corpus.sh --both` 854/854, `MERE_RUBY_VM=1 run_corpus.sh --both` 854/854, and the source gates (dead_defs, dup_defs, gc_roots, meth_writes, name_len, ns_names, bracket_depth). The first run without the VM stopped at corpus 138: another corpus run was going at the same time, and the two share fixed `/tmp` paths. It was run again alone.
