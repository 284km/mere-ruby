# The scratch env of `recv.attr op= v` is a pooled child of the frame, not a copy of its whole chain

Stage 2 of the frame rework (note 552 §17.3), first step.

**The cost.** with_scratch_env gives `recv.attr op= v`, `recv[i] op= v` and an expression's `require` an env to bind their temporaries in (`__opr`, `__opv`, the index temps, `__reqp`). It made that env with lv_flat_pooled: a frame from the pool, into which lv_flat_into wrote every name of every frame up to the top level. test/unit runs `self.assertions += 1` for every assertion, so a test file paid that copy tens of thousands of times. In note 552 §17.6's sample of test_ast, the copy was 86 of the 1,171 samples of string-key work, which was 28% of the main thread.

**The change.** with_scratch_env now takes a pooled child of the frame (blk_env_get, as vm_scoped's scope is) and gives it back with blk_env_put. The callers bind their temporaries in the child and read self and the rest through the chain. lv_flat_pooled has no caller left and is gone.

The rule that nothing read out of the scratch env may be returned still holds: the child's arena is wound back when it goes to the pool, as the copy's was. The callers return what they computed (`set9 v` answers v), never a value read from the env.

**Numbers.**
- test_ast's `test_all_tokens:test/ruby/test_keyword.rb` (72,480 assertions), main 03c2869a against this:

  | | main | this |
  |---|---|---|
  | evaluator | 62.81 G | 61.09 G (−2.7%) |
  | VM | 64.62 G | 62.73 G (−2.9%) |

- Places that write a `"__"` name into a map: 196 before and 196 after. This step removes a copy made at run time, not a writer. The next step moves the frame's less-read entries (`__fid`, `__has_blk`, `__defidx`, `__nest`) to the frame's head and lowers the count.

**Left (from the review of #187, as on main, both executions):** a refinement of `Integer#!` is not used. `!1` is false where ruby gives the refinement's answer. It sits beside the singleton `!` of a builtin value, which loop/2026-11-23-stage10-r54.md records. EUn's arm, which the VM's `!` follows, asks neither a refinement nor a builtin value's singleton class.

## Review of #191

**[Major] A Fiber that stopped inside the value of an op-assign was never reclaimed.** Examples: `o.y += y.yield(1)` and `h[:a] ||= Fiber.yield`, on the evaluator.
- The scratch env was alive while the right side ran, because it was the env the whole op-assign ran in.
- As a pooled child, it is registered in lv_up but not in fb_env_at, so its id was not in fb_rc_eid.
- fb_reclaim's roots marked its parent, the stopped block's env, and through the yielder reached the Fiber. The Fiber could never be given back.
- The flattened copy before this PR had no lv_up link, so main did not have this.

**The fix.**
- The right side now runs in env itself, with no scope alive.
- The reader and the writer each run in a pooled scope of their own, vm_scoped: the answer is copied out of its region before the scope goes back, so the rule that nothing read out of a scratch env is returned still holds.
- EIdxOp is the same: its index temporaries are bound in each scope.
- with_scratch_env is left with the expression-position `require`.

Peak RSS, 4,000 Enumerators each run to the yield and dropped:

| | main | #191 before | now |
|---|---|---|---|
| `o.y += y.yield(1)` | 416 MB | 1,059 MB | 422 MB |
| `h[:a] ||= y.yield(2)` | 433 MB | 1,122 MB | 441 MB |
| `v = y.yield(3); o.y += v` | 439 MB | 430 MB | 445 MB |

A Thread killed while it waits inside the value (`o.y += q.pop`, 3,000 times) peaks at 125 MB on all three builds.

**The cost of two scopes.** test_ast's one file now takes 61.39 G on the evaluator (main 62.77 G, −2.2%) and 65.40 G on the VM (main 65.75 G, −0.5%). Most of the first step's gain on the VM is gone. Correctness came first.

**Recorded, as on main:** `nn&.y += (zz = 1)` with `nn` nil leaves `zz` a NameError, as the review found.
