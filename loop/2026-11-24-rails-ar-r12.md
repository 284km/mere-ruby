# extend calls each module's #extended as soon as that module is in (a regression of #218)

**What went wrong.** #218 made `obj.extend(A, B)` take its modules last first. On the default path, with no module defining `extend_object`, every module was mixed in first and the `extended` hooks were called after. With the order reversed, B's hook ran with A already in front of B:

```ruby
module A; def who = :a; end
module B; def who = :b; def self.extended(o) = p(o.who); end
Object.new.extend(A, B)   # ruby 4.0.9, 4.0.10 and main before #218: :b; main with #218: :a
```

`rb_obj_extend` mixes one module in and calls its `extended` before it takes the next. The review bot marked it on #218 (Major/P2) and it was merged unanswered; work2026-44 caught it after the merge.

**The change.** One loop for both paths. For each module, last first: it is mixed in (by its own `extend_object` when it defines one), and its `extended` is called before the next module is taken. A primitive receiver's singleton is made its dispatch class before the loop, so a hook that calls the receiver finds what the module brought.

**Corpus 973** now has a hook that calls the receiver, for eight kinds of receiver (an object, an Array, a Hash, a String, a Proc, a Module, a Class, an Enumerator): what `who` answers inside each hook, and whether the nearer module is in yet. It also has two `extend`s one after the other, and a hook that extends again. The order of the hooks alone, which is what #218's version recorded, does not show this.

**Checked against ruby 4.0.10** (the reference since #208; `. tools/ref_ruby.sh` names it), on main 30de57d4 and this: `run_corpus.sh --both` 866/866, `MERE_RUBY_VM=1 run_corpus.sh --both` 866/866; the source gates (dead_defs, dup_defs, gc_roots, meth_writes, name_len, ns_names, bracket_depth); tools/loop_rss_check.sh, nine of nine.

A first corpus run stopped at corpus 499 on `Prism::VERSION` ("1.9.0" on the reference, "1.8.2" here). That was the reference: an editor's language server had installed prism 1.9.0 into the pinned ruby's own gem directory that day. The gems were removed and the corpus was run again from the start; 499 matches. #224 makes tools/ref_ruby.sh stop on such a directory.

**Left, as on main before #218.** On a String, an Array or a Hash, a method of one extended module that calls `super` into another extended module's raises NoMethodError, though `singleton_class.ancestors` lists both in the right order. An object's does it right.
